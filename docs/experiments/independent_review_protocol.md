# 독립 검수 에이전트 운영 규칙

## 목적

실험 수행 에이전트의 설명과 실제 증적이 다를 때 완료 주장이 먼저 나가는 일을 막는다.
검수 에이전트는 새 컨텍스트에서 원 요구사항과 파일만 읽으며 수행 에이전트의 결론을
전제로 삼지 않는다. OpenAI 공식 모델 지침도 품질 향상을 위해 작업을 서브에이전트에
분담하도록 동작을 명시할 수 있다고 설명한다.

## 역할 분리

| 역할 | TOML 설정 | 모델·추론 강도 | 책임 | 금지 사항 |
| --- | --- | --- | --- | --- |
| 실험 에이전트 | `.codex/agents/poi-experiment-runner.toml` | `gpt-5.6-sol`, `xhigh` | 코드, 실험, 표, 그림, 보고서 생성 | 자기 결과만으로 최종 완료 선언 |
| 검수 에이전트 | `.codex/agents/independent-experiment-audit.toml` | `gpt-6-astra`, `medium` | 원 계획과 실제 원자료·코드 독립 대조 | 실험 코드나 기존 증적 수정 |
| 자동 감사 | 실행 스크립트 | 결정적 코드 | cardinality, split, 파일 형식 검사 | 보고서 존재만으로 의미적 요구 충족 판정 |

프로젝트 전역 멀티 에이전트 설정은 `.codex/config.toml`에 둔다. 모델명, 추론 강도,
역할별 핵심 지침은 Markdown 문서에만 선언하지 않고 역할별 TOML에 고정한다. 이 문서는
역할 호출 순서, 증적 검사 항목, 완료 판정처럼 TOML 값만으로 표현할 수 없는 운영 계약을
담는다. 두 파일의 내용이 다르면 TOML의 실행 설정과 이 문서의 완료 게이트를 모두
충족해야 하며, 임의로 한쪽을 완화해서는 안 된다.

실험과 검수는 반드시 서로 다른 에이전트로 실행한다. 검수 에이전트는
`fork_turns="none"`인 새 컨텍스트로 시작한다. 프롬프트에는 원 요구사항 문서, artifact
경로, 검사 항목만 전달한다. “완료됐는지 확인하라” 대신 “각 요구사항을
PASS/PARTIAL/FAIL/NOT_RUN으로 판정하라”고 지시한다. 검수 보고서에는 실제 요청한 모델
`gpt-6-astra`, 추론 강도 `medium`, 역할과 검사 범위를 기록한다.

현재 세션에서 이미 실행 중인 루트 에이전트의 모델은 작업 도중 교체할 수 없다. 실제
실험 작업은 `poi_experiment_runner` 역할로 시작하고, 검수는
`independent_experiment_audit` 역할로 시작한다. 역할 TOML에 고정된 모델과 추론 강도를
호출 시 별도 값으로 덮어쓰지 않는다.

## 필수 판정표

검수 결과는 최소한 다음 열을 포함한다.

| 열 | 의미 |
| --- | --- |
| requirement | 원 계획의 구체적인 요구사항 |
| expected | 필요한 지역·조건·seed·행·파일 수 |
| observed | 원자료에서 직접 센 값 |
| verdict | PASS, PARTIAL, FAIL, NOT_RUN |
| evidence | 정확한 파일 경로와 필요한 경우 열 이름 |
| limitation | 해석 제한 또는 누락 범위 |

보고서 머리말에는 다음 실행 정보를 반드시 둔다.

```text
role: independent_reviewer
requested_model: gpt-6-astra
reasoning_effort: medium
fork_context: none
review_scope: <plan and artifact paths>
```

## POI 실험 필수 검사

1. 입력은 좌표 2개와 업종 코드 3개이며 지역명·주소·식별자 누수가 없는가
2. 34,000건의 train 23,800, validation 3,400, 잠금 test 6,800 분할이 유지되는가
3. 공격 데이터가 32조건·870,400행이며 train/validation만 포함하는가
4. 좌표 거리, 범주 L0, 유효 범주 조합과 label 보존 제약을 모든 행이 통과하는가
5. clean 모델 비교가 8모델×17지역×3seed인 408개 지표 행을 포함하는가
6. 공격 평가가 33조건×17지역×3seed인 1,683개 지표 행과 요청한 5개 지표를 포함하는가
7. SHAP beeswarm/dot이 17지역×clean/adversarial인 34개이며 bar chart로 대체되지 않았는가
8. LIME이 계획에 명시된 지역별 대표 사례를 모두 포함하는가
9. CCA, correlation, paired 검정, chi-square 계열 검정과 다중검정 보정이 실제 표에 있는가
10. 자체 방어 모델, URE-RF, 탐지 후 지역분류, 앙상블, sensitivity, stability와 ablation이
    문서 계획만 존재하는지 실제 결과까지 존재하는지 구분했는가
11. test가 모든 선택을 고정하기 전에 사용되지 않았는가
12. 모든 그림이 PNG 300dpi이고 SVG가 없는가

## 완료 게이트

수행 에이전트는 다음 세 조건을 모두 만족한 뒤에만 해당 범위를 완료로 기록한다.

1. 자동 감사가 성공한다.
2. 독립 검수의 해당 범위 항목이 모두 PASS다.
3. 보고서의 완료·미완료 표가 독립 검수 결과와 일치한다.

부분 완료 항목이 있으면 상위 단계도 부분 완료로 쓴다. 기존 성공 마커가 있더라도 독립
검수에서 누락이 확인되면 성공 마커의 검사 범위가 부족했다고 명시하고 새 검수가 통과할
때까지 최종 완료 근거로 사용하지 않는다.

## 현재 발견된 감사 규칙의 공백

기존 `scripts/audit_attack_scope.py`는 SHAP 34개와 17개 지역·2조건을 확인했지만 LIME의
지역 수와 조건 수는 확인하지 않았다. 그 결과 Seoul clean 대표 사례 하나만 존재하는데도
감사를 통과했다. 현재 전달본은 이 제한을 명시해야 하며, 지역별 LIME을 생성한 뒤 새
독립 검수를 수행해야 한다.
